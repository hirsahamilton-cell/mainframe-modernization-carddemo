# CardDemo card reader (Java port of CBACT02C)

Java 17 port of the `READCARD` batch step (`app/jcl/READCARD.jcl`) and
`app/cbl/CBACT02C.cbl`. The program reads the card KSDS sequentially in key order and displays every
150-character `CARD-RECORD` as stored, including its filler bytes.

| COBOL | Java |
| --- | --- |
| `0000-CARDFILE-OPEN`, `1000-CARDFILE-GET-NEXT`, `9000-CARDFILE-CLOSE` | `io.CardFile` |
| `9910-DISPLAY-IO-STATUS`, `9999-ABEND-PROGRAM` | `io.CardFileException`, exit code 12 |
| `CARD-RECORD` in `CVACT02Y` | `model.Card`, `io.CardRecords` |
| `PROCEDURE DIVISION` | `CardFileReaderMain` |

`CardRecords` parses and formats the fixed-width card record. The embossed name is stored right-trimmed
and padded when formatted; all other text fields, including the 59-byte filler, are retained. `CardFile`
skips blank lines, rejects duplicate card keys, and sorts input by the 16-byte card number to model
sequential KSDS access.

## Build and run

```sh
mvn test
mvn package
java -jar target/card-reader-1.0.0-SNAPSHOT.jar CARDFILE
```

`CARDFILE` is a US-ASCII, one-record-per-line file such as `../../data/ASCII/carddata.txt`. The CLI prints
the original start/end messages and complete 150-character records. An incorrect argument count prints
usage on stderr and returns 8; file errors print the abend lines and return 12.

## COBOL baseline

`cobol-harness/run-cobol-baseline.sh [CARDDATA]` compiles the unmodified `CBACT02C.cbl` with GnuCOBOL
3.x and the local `CARDLOAD.cbl` loader, which loads the input into an indexed file in random-key mode.
It writes DISPLAY output followed by `RETURN-CODE n` to `cobol-harness/out/readcard-sysout.txt`.
If the input path does not exist, the harness runs against a nonexistent CARDFILE instead. The checked-in
`src/test/resources/cobol-baseline/` outputs are generated by this script for the sample, edge, empty, and
missing-file scenarios.

To regenerate the baselines from this module directory:

```sh
OUT_DIR=src/test/resources/cobol-baseline/sample cobol-harness/run-cobol-baseline.sh \
  ../../data/ASCII/carddata.txt
OUT_DIR=src/test/resources/cobol-baseline/edge cobol-harness/run-cobol-baseline.sh \
  src/test/resources/scenarios/edge.txt
OUT_DIR=src/test/resources/cobol-baseline/empty cobol-harness/run-cobol-baseline.sh \
  src/test/resources/scenarios/empty.txt
OUT_DIR=src/test/resources/cobol-baseline/missing cobol-harness/run-cobol-baseline.sh \
  src/test/resources/scenarios/missing.txt
```

## Differences from COBOL

- Java reads and validates the whole input before displaying any card. If a record is invalid or a card
  key repeats, no earlier cards are printed; COBOL displays earlier records before an error encountered
  during the sequential read.
- Missing/unreadable input uses the COBOL open-error text with status `0035`; record validation and
  duplicate-key errors include a Java-specific line number and explanation.
- The IBM Language Environment routine `CEE3ABD` is unavailable under GnuCOBOL. Its missing-file baseline
  therefore includes the COBOL error DISPLAY lines and a non-zero `RETURN-CODE`, while Java reports the
  same error lines and returns 12 without attempting that external call.
