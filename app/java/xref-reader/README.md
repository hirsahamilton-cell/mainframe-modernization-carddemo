# CardDemo card cross-reference reader (Java port of CBACT03C)

Java 17 port of the `READXREF` batch step (`app/jcl/READXREF.jcl`) and
`app/cbl/CBACT03C.cbl`. The program reads the card cross-reference KSDS sequentially in key order and
displays every 50-character `CARD-XREF-RECORD` (copybook `CVACT03Y`) as stored, including its filler bytes.

| COBOL | Java |
| --- | --- |
| `0000-XREFFILE-OPEN`, `1000-XREFFILE-GET-NEXT`, `9000-XREFFILE-CLOSE` | `io.XrefFile` |
| `9910-DISPLAY-IO-STATUS`, `9999-ABEND-PROGRAM` | `io.XrefFileException`, exit code 12 |
| `CARD-XREF-RECORD` in `CVACT03Y` | `model.CardCrossReference`, `io.XrefRecords` |
| `PROCEDURE DIVISION` | `XrefFileReaderMain` |

`XrefRecords` parses and formats the fixed-width record: 16-byte card number, 9-digit customer id,
11-digit account id and 14-byte filler (kept as-is). `XrefFile` skips blank lines, rejects non-numeric ids
and duplicate card keys, and sorts input by card number to model sequential KSDS access.

## Build and run

```sh
mvn test
mvn package
java -jar target/xref-reader-1.0.0-SNAPSHOT.jar XREFFILE
```

`XREFFILE` is a US-ASCII, one-record-per-line file such as `../../data/ASCII/cardxref.txt`. The CLI prints
the original start/end messages and each complete 50-character record once. An incorrect argument count
prints usage on stderr and returns 8; file errors print the abend lines and return 12.

## COBOL baseline

`cobol-harness/run-cobol-baseline.sh [CARDXREF]` compiles the unmodified `CBACT03C.cbl` with GnuCOBOL
3.x and the local `XREFLOAD.cbl` loader, which loads the input into an indexed file in random-key mode
(so unsorted input works). It writes DISPLAY output followed by `RETURN-CODE n` to
`cobol-harness/out/readxref-sysout.txt`. If the input path does not exist, the harness runs against a
nonexistent XREFFILE instead. The checked-in `src/test/resources/cobol-baseline/` outputs are generated by
this script for the sample, edge, empty, and missing-file scenarios.

To regenerate the baselines from this module directory:

```sh
OUT_DIR=src/test/resources/cobol-baseline/sample cobol-harness/run-cobol-baseline.sh \
  ../../data/ASCII/cardxref.txt
OUT_DIR=src/test/resources/cobol-baseline/edge cobol-harness/run-cobol-baseline.sh \
  src/test/resources/scenarios/edge.txt
OUT_DIR=src/test/resources/cobol-baseline/empty cobol-harness/run-cobol-baseline.sh \
  src/test/resources/scenarios/empty.txt
OUT_DIR=src/test/resources/cobol-baseline/missing cobol-harness/run-cobol-baseline.sh \
  src/test/resources/scenarios/missing.txt
```

## Differences from COBOL

- **Bug fix: each record is printed once.** CBACT03C DISPLAYs `CARD-XREF-RECORD` both inside
  `1000-XREFFILE-GET-NEXT` and again in the main loop, so every record appears twice in SYSOUT (CBACT02C,
  the card reader, has the inner DISPLAY commented out). `CobolComparisonTest` checks that the COBOL
  output is exactly the Java output with each record line doubled.
- Java reads and validates the whole input before displaying any record. If a record is invalid or a card
  key repeats, no earlier records are printed; COBOL displays earlier records before an error encountered
  during the sequential read. COBOL does not validate the numeric ids at all; Java rejects them.
- Missing/unreadable input uses the COBOL open-error text with status `0035`; record validation and
  duplicate-key errors include a Java-specific line number and explanation.
- The IBM Language Environment routine `CEE3ABD` is unavailable under GnuCOBOL. Its missing-file baseline
  therefore includes the COBOL error DISPLAY lines and a non-zero `RETURN-CODE`, while Java reports the
  same error lines and returns 12 without attempting that external call.
